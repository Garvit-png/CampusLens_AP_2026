-- Q2: Hashtag GIN Search
-- EXPLAIN ANALYZE command:

EXPLAIN ANALYZE
SELECT
    p.id, p.image_url, p.thumbnail_url, p.caption, p.hashtags, p.uploaded_at
FROM   photos p
WHERE  p.hashtags  @> ARRAY['Damru26']
  AND  p.college_id = 'a1b2c3d4-0000-0000-0000-rishihood001'
ORDER BY p.uploaded_at DESC;

-- Interpretation:
-- The GIN index (idx_photos_hashtags) is the key asset here. GIN indexes invert array values,
-- creating an entry per element, so the @> (array contains) operator is answered by a direct
-- index probe rather than a full scan. The planner combines GIN bitmap and college bitmap via
-- BitmapAnd, fetching only the intersection of rows matching both conditions from the heap.
-- Without this GIN index, every photo row would need a linear array scan — O(n) vs O(log n).
